# 2026-10-30 轻量 OCR 横评协议

## 任务与固定输入

用户授权自主选取轻量方案、测试领域和范围。使用 balanced60-v1：中文及混排40份、英文20份，来源和哈希见 data/manifests/balanced60.json。另6份开发图只用于接通与预检，不参与60份质量汇总

所有引擎使用相同RGB PNG，长边最多2000像素，不放大小图；PDF统一渲染第1页，禁止利用原有文字层。保留输入哈希与原始文件。不是各引擎最佳精度配置，也不是原始分辨率上限测试；内部缩放和检测策略仍由引擎决定

设备为本机Apple Silicon、64 GiB内存，CPU主对照固定相关线程环境变量为4，串行运行不同引擎。线程数为配置约束，不保证第三方库全部遵循。版本与模型配置写入各引擎setup.json，模型缓存放用户目录，当时Python新增依赖放项目.venv；现已迁移至用户级工具，见[CLI使用](cli-setup.md)

## 轻量范围与准入

预定候选为RapidOCR、PaddleOCR、Tesseract、EasyOCR、Docling、MinerU、GLM-OCR和PaddleOCR-VL。新增单方案模型权重软预算1 GiB，不为本轮配置远端GPU或付费API；文档流水线可按依赖复杂度缩减。未运行不代表效果差

先跑开发6份，至少5份成功且中位耗时≤30秒才扩至60份。逐样本超时120秒，预热180秒；预检进程总上限420秒、正式进程1200秒。初始化/下载失败单独记环境未就绪。首次预热可能包含下载，不能视为纯推理时间

## 质量口径

统一NFKC、casefold并去除空白，保留标点、数字；不做简繁转换。原标注未逐字人工复核，此次为小样本工程筛选，不是官方榜单

- ReCTS裁剪文字行：编辑距离/参考字符数（CER，越低越好），允许大于100%；另报完全匹配数。全文识别流水线直接读取裁剪图，没有单独指定“仅识别”模式
- EST-VQA/LSVT：标注目标答案是否作为连续文本出现在输出中。只测答案文本检出，不测理解问题或完整图像转录
- FUNSD/XFUND：实体原文完整出现在输出中才算命中；按实体字符数加权，先算每页再宏平均。不评价字段关联
- OmniDocBench：采用非ignore文本块和HTML表格单元格，去除开头标题井号；排除abandon、figure、孤立公式/公式标题。按完整文本块/单元格匹配的字符覆盖率算每页、再宏平均。长块中一个错字可能使整块失分，公式和行序会影响覆盖，不是逐字符准确率
- olmOCR-bench：自定义严格子串present/absent及先后order检查，分别列分子分母。未实现官方模糊容忍、大小写或位置限制等规则，不称官方分数；空输出/失败不能靠absent获分

失败页保持在分母内，文本为空；不将各组混成总准确率。没有建立表格结构/公式的人工金标准，所以结构仅能报告产物与观察，不做“结构准确率”排行

## 计时与证据

分别记录环境准备、初始化、预热、单页、60份推理总和、进程墙钟耗时；单次运行无置信区间。Tesseract逐页CLI启动时间包含在逐页耗时中，其他模型在同一进程复用。下载和依赖安装可能与测试重叠，是本机工程测量而非隔离实验室性能榜

每个样本输出JSON含原始文本、状态、耗时、准备输入哈希，支持检测框的引擎额外保留坐标。详细输出本地data/outputs/bench-20261030，精简汇总进入data/reports。进程RSS只用于观察，Tesseract子进程不包含在Python主进程RSS内，不横向排名

## 命令

```sh
uv sync --extra easy
uv run scripts/bench-prepare.py
uv run scripts/bench-run.py rapid paddle tesseract easy docling
uv run scripts/bench-score.py
```

RapidOCR、PaddleOCR、Docling环境由uv tool dir定位，复用用户级安装。现有完成结果不会重复跑；新测试应更换run_id并对应修改脚本中的输出目录，当前脚本是本次固定实验入口
