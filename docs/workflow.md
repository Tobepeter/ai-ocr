# OCR 实验工作流

本项目已有Gradio四方案对比、三轮评测与轻量评分依赖；当前执行入口与规则以[评价协议v3.1](ocr-evaluation-v3.md)为准

## 1. 确定一个目标

先选截图识字与坐标、扫描 PDF 文字层、文档转 Markdown/表格或字段提取之一，再参考 [方案概览](research/ocr-landscape.md) 选一个引擎。第一轮只用少量固定样本，不为覆盖候选清单安装全部工具

## 2. 冻结物料和答案

正式比较先按 [多来源抽样方案](research/ocr-materials.md) 冻结来源、分层和文档/模板隔离；单样本只验证链路，不能代替质量评测

按照 [物料约定](../data/README.md) 保存原始输入、来源和 SHA256，并填写 [物料清单](../data/manifests/materials.csv)。原始输入不覆盖，裁剪、旋转和缩放另存为派生物料，记录源文件与参数。先校对参考答案再看模型输出；未校对的样本只能做链路检查，不能用于准确率结论

## 3. 核对依赖并最小运行

按选定版本的官方文档确认硬件、许可证、后端与安装命令，记录引擎版本、模型 ID/revision、设备、精度和线程数。优先复用官方模型缓存。项目轻量依赖由uv.lock冻结，模型工具复用用户级环境；按CLI说明安装并验证运行命令

用单样本确认能读输入、保存原始结果并正常退出，随后人工核对文字。链路通过和识字质量分开记录

## 4. 保存完整运行证据

当前运行目录使用 `data/outputs/{run_id}/{engine}/{case_id}.json`，模型版本与参数保存在该轮元数据中。保存命令、参数、输入哈希、原始输出、标准化结果、错误和退出状态；失败与空输出也保留

下载、加载、预热、纯推理分别计时，批量实验复用模型实例。改变输入、模型或关键参数就创建新 run_id，避免混合条件。运行完成须有结果和正常退出证据，不能仅凭输出文件存在判断

## 5. 对照与报告

正式比较使用同一批输入和预先确定的规范化规则，保留原始文字及原始分数。按任务检查文字 CER/WER、漏字与补字、坐标、阅读顺序、表格结构；不合并成未定义的“准确率”。CPU 与加速后端分开报告

报告存入 `data/reports/`，至少包含目标、case_id、物料清单、环境与模型版本、复现命令、结果、耗时、失败项、限制及原始产物位置；小型 JSON/CSV 汇总可随报告进入 Git。无实测时明确写“候选”或“待验证”

## 6. 收尾与接力

更新报告索引；可复用结论写正式文档，当前焦点、下一步和阻塞写本机任务进度。提交前检查 diff、物料授权与体积、清单恢复方式；必要复现资料不能仅保存在 `.temp/` 或个人绝对路径中

单元测试按实现中的真实边界添加，如坐标转换、分页顺序、损坏输入和原始结果保留；当前回归覆盖评分、目录隔离、中止清理、缺失计时与网页异常隔离，必要时再做少量真实引擎验收
