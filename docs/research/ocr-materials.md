# OCR 物料来源与分层抽样方案

当前已完成 [中文优先 60 份选样](../../data/reports/balanced60-materials.md)：40 中文及混排 + 20 英文，候选池 76 份。下文 120+10 为历史方案，不是当前运行目标

调研日期：2026-10-30。使用 Exa 进行了 4 轮搜索，请求 20 条结果（含重复），并读取关键官方页面。本文件是来源调研和拟议协议，未下载数据、核验完整数据包或运行模型。来源网站可读不等于下载及再分发条件已通过

## 从 ai-voice 借鉴什么

本轮直接阅读参考工程的 `docs/test-materials.md`、`docs/fair-benchmark.md`（两者位于其本机任务目录）及 `scripts/prepare_fair_stt.py`

- 早期 8 条烟测只覆盖 AISHELL 与 LibriSpeech dummy，不能据此排模型名次
- 曾规划 200 条多来源语音加长音频；最终协议实际为 AISHELL 40、ASCEND 40、LibriSpeech 20，加 3 条静音。规划和实采不能混为一谈
- 实现是固定覆盖抽样：部分固定间隔取行，ASCEND 固定种子打乱后按说话人轮转；不是对全部来源做严格分层随机抽样
- 保存原始文件、转换文件、哈希、source/split/speaker/session；不依据模型输出选样
- 标注仍可能有问题：4 条参考含 [UNK] 的样本对全部模型统一排除质量评分，性能输入保持不变
- 不同镜像不是不同语料；新版本发布不证明数据未见于训练；自录留出样本补充公开基准

OCR 应把 speaker/session 对应为原始文档、模板、站点、拍摄场景和书写者。页数、裁剪数与独立来源数必须分开报告

## 公开来源地图

以下为候选池，来源明确但尚未完成逐包访问、许可和标注验收；表中的用途不代表其全部标注都是人工金标准

| 来源 | 能补充什么 | 标注和使用边界 |
| --- | --- | --- |
| [OmniDocBench](https://github.com/opendatalab/OmniDocBench) | 多类型文档，含论文、报告、书刊等；文字、公式、表格、阅读顺序 | 当前主线与旧版本规模不同，冻结 revision 后按语言和文档类型抽样，不能只取示例页；论文文档不能替代截图场景 |
| [olmOCR-bench 数据卡](https://huggingface.co/datasets/allenai/olmOCR-bench/raw/main/README.md) | 英文旧扫描、多栏、小字、数学、表格等专项检查 | 数据卡列出 1,403 PDF / 7,010 测试；主要是文字存在/缺失、顺序、表格邻接等断言，不是完整逐字转录；部分断言借助模型生成，需复核；数据卡列 ODC-BY-1.0，仍保留原始文档来源 |
| [CTW](https://ctwdataset.github.io/) | 中文街景、复杂背景、弱光、远距离及遮挡 | 官方提供字符标注与属性；是自然场景文字，不能视为 GUI 截图；需要核对 split 和公开答案范围 |
| [RCTW-17 论文](https://arxiv.org/abs/1708.09585) | 手机照片与少量数字截图，中文行级检测与识别 | 与 CTW 是不同项目，不按名称相似合并；标注含难识别标记，不能擅自当空文本 |
| [ReCTS 论文](https://arxiv.org/abs/1912.09641) | 中文商铺招牌，字体与排列复杂 | 同一商家或相近拍摄应分组；部分任务有多种允许的标注方式，需沿用官方匹配规则 |
| [SROIE](https://rrc.cvc.uab.es/?ch=13) | 扫描收据的检测、文字与字段提取 | 票据 OCR 与字段抽取分开；不能代表中文发票；获取入口与许可待采集前确认 |
| [FUNSD](https://guillaumejaume.github.io/FUNSD/) | 噪声扫描表单，文字、实体及关系 | 199 份标注表单，规模有限；按文档/模板划分，不能把词框数量当独立样本量 |
| [PubTabNet](https://github.com/ibm-aur-nlp/PubTabNet) | 科学文献表格图片、HTML 结构与单元格 | 来源集中于 PMC，不能代表所有财务表格；标注来自 PDF/XML 对齐，需复核；README 同时含历史测试集说明和后续竞赛发布入口，采集时核对具体版本及可用答案 |
| [DocLayNet](https://github.com/DS4SD/DocLayNet) | 金融、科学、专利、招标、法律、手册等版面 | 主体是人工版面框；额外 JSON 为 PDF 数字文本单元，不能直接声称完整人工 OCR 真值；目前仅作为版面补充候选 |
| [CASIA-HWDB](https://nlpr.ia.ac.cn/databases/handwriting/Download.html) | 中文手写，按书写者分组 | 单字识别与整页/行识别必须分开，优先研究 HWDB2.x 页/行数据；DGRL 需要转换，不把在线笔迹轨迹当扫描图 |
| [美国国会图书馆报纸](https://guides.loc.gov/chronicling-america/additional-features) | 独立档案来源的老报纸、多栏、小字、扫描退化 | 支持公开 API，但现成文字是 OCR；[官方说明](https://guides.loc.gov/chronicling-america/download-and-view)明确存在识别错误，必须人工校对才可评分；逐项查看[权利说明](https://www.loc.gov/collections/chronicling-america/about-this-collection/rights-and-access/) |
| 新采集实际截图/拍照 | 中文软件、网页、终端、小字、缩放和实际使用习惯 | 在模型版本冻结后采集并人工标注，降低特定图像训练重合风险；不能证明网页文字未进入训练；私有输入留本地 |

镜像、原始文档与派生数据必须追溯：olmOCR-bench 的部分资料来自 Library of Congress 和 Internet Archive，追加同一文档不能算新的独立来源。PubTabNet 与其他 PMC 衍生集也需检查文章 ID

## 建议首轮规模：120 个页面/图像单位，加 10 个负例

这是可调整的工程起步配额，不是统计充分性的保证，也不是已采集清单。正式运行前先用另选的 6–10 个开发样本调通链路，不从最终留出样本反复调参

| 分层 | 配额 | 来源安排 |
| --- | ---: | --- |
| 实际截图留出 | 30 | 新采集，至少 5 个应用/站点，每个最多 6 张；覆盖中英混排、小字、深浅色和缩放，避免相邻滚屏重复 |
| 完整文档 | 30 | OmniDocBench 分文档类型、语言、版式取样，至少 15 份原始文档，每份最多 2 页 |
| 自然场景文字 | 20 | CTW 与 RCTW/ReCTS 中至少两个来源，各约 10 张；不伪称截图效果 |
| 表格与票据表单 | 20 | PubTabNet 10、SROIE 5、FUNSD 5；结构和字段按任务分别评分 |
| 手写 | 10 | CASIA 页/行数据，尽可能覆盖至少 5 位书写者，单字数据不用于替代 |
| 历史扫描 | 10 | olmOCR-bench 5、独立图书馆文档 5，检查原始文档无重叠；前者用断言，后者校对后做文字评分 |
| 负例（单列） | 10 | 空白、无字图片、纹理/图标，检查凭空生字；合成负例标记 synthetic，不冒充真实来源 |

目标语言覆盖中文至少 60/120、中英混排至少 20/120（混排可计入中文覆盖），英文作为对照。采集后核实是否达成，不为了配额改标签。同一原始数据集尽量不超过主集 30%；缺少来源时登记缺口，不重复图片或改用同一来源补满而不说明

截图、自然场景、整页文档、表格、手写均单列结论，不产生把不同任务揉在一起的统一“准确率榜单”。若当前用途只需截图，可先执行截图分层，但结论只覆盖该分层

## 抽样、去重与冻结

1. 先确定任务和合格条件，读取可获取的候选元数据并保存快照、revision、split、原始 ID 和过滤原因；不只抓搜索排名靠前或展示页
2. 在来源 × 场景 × 语言的层内，先选独立文档/模板/场景/书写者，再选页或图。固定种子 `20261030`，保存完整候选池、候选排序和选中 ID；种子本身不足以复现变化后的上游列表
3. 原始文件做 SHA256 去重，另检查渲染图的近重复、同文档不同分辨率、裁剪和改名；近重复只作待审线索，不自动丢弃真实差异
4. 开发与最终留出按 document/template/site/writer 等组隔离，不能随机拆同一文档的页；缺失组信息则标记 unknown 并限制泛化结论
5. 优先官方 test 或可获得答案的 validation，记录实际 split。只有 train 有答案时可做探索，不能称为独立泛化测试
6. 保存模型版本、物料名单及参考答案哈希后再运行。原件只读，渲染 DPI、方向、裁剪和图像转换记录在派生元数据中；既有 PDF 文字层提取与纯图像 OCR 分开评测
7. 已有参考也要验收；机器转录仅为草稿。争议项按事前规则统一修订/排除，记录版本，对全部模型重算，不根据模型输出来选最有利答案

## 报告与偏差控制

- 按来源和场景列样本数、独立文档/模板/书写者数、语言、字符量、难例比例、失败及空输出；不能仅列总页数
- 同任务保留逐样本成对结果、微平均与按来源汇总；不要让一份长文档的字符量淹没全部截图。需要区间时按原始文档/模板聚类估计，不把每个文字框当独立证据
- 文字识别报告原始及预先定义的规范化 CER/WER；金额、小数点、负号、日期、代码标识符不得随意消掉
- 文档额外检查漏段、重复、阅读顺序；表格检查结构和单元格对应；字段提取检查字段值；无字负例检查幻觉
- 公开基准可复现，但可能与训练/开发重合；多来源只能减少单一来源偏差，不能证明无污染。实际用途留出集单独报告
- 下载/解码失败也记录来源和数量，替补沿冻结抽样顺序，不挑识别容易的图
